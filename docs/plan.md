# Health Value Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a small, working orthopedic value dashboard (Value and Data tabs) with made-up data, R-validated
statistics, CI, and a published Docker image, plus the starter kit and the example cards, so a learner can see a real
development workflow end to end.

**Architecture:** One Shiny for Python app. `app/schema.py` is the only place that knows column names; `app/data.py`
loads and validates a CSV against it; `app/stats.py` holds pure statistics functions checked against golden CSVs
written by a base-R script. Every session shares one `reactive.file_reader` on `DATA_PATH`, so an upload or a copied
file reloads all dashboards. The app ships as a multi-arch Docker image published to GHCR on every merge to `main`.

**Tech Stack:** Python 3.12, uv, ruff, pytest, shiny, shinywidgets, plotly, pandas, numpy, scipy, playwright
(screenshots only); R 4.4.1 in `rocker/r-ver:4.4.1` (reference answers only); Docker with buildx; GitHub Actions;
GHCR.

**Spec:** [design.md](design.md)

**Repo:** https://github.com/tahardi/health-value-dashboard (public)

## How to Use This Plan

Each task is one Jira card and one PR in the `HVD` project. The card key is next to each task title. Epics: Foundation
HVD-2, Data and Statistics HVD-3, Dashboard HVD-4, Delivery HVD-5, Starter Kit HVD-6, Demo HVD-7.

2. Work only inside that worktree. Never commit to `main`.

creates its own worktree at the location the starter kit's `CLAUDE.md` names.

## Global Constraints

- Never add code comments, except the `# given`, `# when`, `# then` markers in tests.
- Lines under 100 characters (`line-length = 100` in ruff). Long signatures and calls: one argument per line.
- Type hints on every function signature.
- Keep each file focused on one subject.
- Tests live in `tests/test_<module>.py`. One test function per function under test, named `test_<function>`, with all
  its cases inside, table-driven with `@pytest.mark.parametrize` where possible. Every test has `# given`, `# when`,
  `# then` sections.
- Add dependencies with `uv add` (dev tools with `uv add --dev`). Commit `uv.lock`. Never `pip install`.
- Python `requires-python = ">=3.12"`, `.python-version` contains `3.12`.
- App code in `app/`, imported as the `app` package (`from app.schema import ...`). Tests import the same way.
- Screens and statistics never hardcode a column name except through the constants in `app/schema.py`.
- The repo is public. Never commit real patient, financial, or company data. All data is generated by
  `scripts/generate_data.py`.
- Makefile recipes with several flags: command on the first line, one flag per line, each ending with `\`.
- Statistics: 95% CI for a mean is `mean ± t(0.975, n - 1) * sd / sqrt(n)` with sample sd (ddof 1). With fewer than 2
  values the CI bounds are NaN (R: `NA`). With 0 values the mean is NaN too.
- Blank cells are allowed only in `measure` columns. Each statistic drops blanks for its own measure and reports that
  measure's own count.
- Low volume threshold: 10 cases. Port: 8000. Env vars: `DATA_PATH`, `SAMPLE_PATH`.
- Image name: `ghcr.io/tahardi/health-value-dashboard`, tags `latest` and the 7-character commit sha.

## Review Focus

1. **A surgeon has 1 case, or every `function_post` for a surgeon is blank, after filtering.** Expect NaN CI bounds
   (and NaN mean for 0 values), shown as "–" in the table, never a crash or an R/Python mismatch. Pinned in T-T1
   (`test_mean_ci` cases for n=0 and n=1; golden data includes a 1-case surgeon) and T-A2 (`test_summary_table`).
2. **Filters leave zero rows.** Expect "No cases match these filters." in place of the chart and table, headline
   numbers shown as "–". Pinned in T-A1 (`test_apply_filters` empty result) and T-A2 (`test_value_map` with an empty
   summary).
3. **A CSV saved from Excel** (UTF-8 BOM, Windows line endings, `TRUE`/`FALSE`, spaces around header names). Expect it
   to load cleanly. Pinned in T-D1 (`test_load` cases).
4. **The wrong file is uploaded** (an `.xlsx`, an empty file, or a CSV with only headers). Expect a plain error and the
   current data left untouched. Pinned in T-D1 (`test_load` errors) and T-A3 (`test_replace_data`).
5. **Someone copies a broken file straight onto the server.** Expect every dashboard to keep showing the last good
   data and the Data tab to show the errors. Pinned in T-A1 (`test_reload`).

## Epic: Data and Statistics (HVD-3)

### T-D1: Schema and Loader (HVD-10)

**Workflow:** as in "How to Use This Plan".

**Files:**

- Create: `app/schema.py`, `app/data.py`, `tests/test_schema.py`, `tests/test_data.py`

**Interfaces:**

- Produces, in `app/schema.py`:
  - `class Kind(StrEnum)`: `CATEGORY = "category"`, `NUMBER = "number"`, `BOOLEAN = "boolean"`, `DATE = "date"`
  - `class Role(StrEnum)`: `ID = "id"`, `DIMENSION = "dimension"`, `MEASURE = "measure"`, `DATE = "date"`
  - `@dataclass(frozen=True) class Column`: `name: str`, `label: str`, `kind: Kind`, `role: Role`,
    `filter: bool = False`, `higher_is_better: bool | None = None`
  - `COLUMNS: tuple[Column, ...]` (table below, in that order)
  - Constants: `CASE_ID = "case_id"`, `SURGEON = "surgeon"`, `PROCEDURE = "procedure"`, `FACILITY = "facility"`,
    `SURGERY_DATE = "surgery_date"`, `COST = "total_cost"`, `FUNCTION_PRE = "function_pre"`,
    `FUNCTION_POST = "function_post"`, `GAIN = "function_gain"`
  - `def filters() -> list[Column]` (dimensions with `filter=True`, in `COLUMNS` order)
  - `def measures(kind: Kind | None = None) -> list[Column]` (measure columns, optionally of one kind)
  - `def rate_measures() -> list[Column]` (shorthand for `measures(Kind.BOOLEAN)`)
- Produces, in `app/data.py`:
  - `class DataError(Exception)` with attribute `errors: list[str]`; `str(err)` is the errors joined with `"; "`
  - `def load(source: str | Path | IO[bytes]) -> pd.DataFrame`

`COLUMNS`:

| name | label | kind | role | filter | higher_is_better |
|---|---|---|---|---|---|
| case_id | Case | category | id | | |
| surgeon | Surgeon | category | dimension | | |
| procedure | Procedure | category | dimension | yes | |
| facility | Facility | category | dimension | yes | |
| payer | Payer | category | dimension | | |
| age_group | Age group | category | dimension | | |
| sex | Sex | category | dimension | | |
| asa_class | ASA class | category | dimension | | |
| surgery_date | Surgery date | date | date | | |
| length_of_stay_days | Length of stay (days) | number | measure | | False |
| total_cost | Total cost ($) | number | measure | | False |
| implant_cost | Implant cost ($) | number | measure | | False |
| complication | Complication | boolean | measure | | False |
| readmit_30d | Readmitted within 30 days | boolean | measure | | False |
| function_pre | Function score before | number | measure | | True |
| function_post | Function score after | number | measure | | True |

`load` rules:

- Read with `pd.read_csv(..., dtype=str, keep_default_na=False, encoding="utf-8-sig")`. Strip whitespace from header
  names and cells. Empty string means blank.
- If reading raises (not a CSV, binary file), errors = `["could not read the file as CSV"]`. If there are no data rows:
  `["the file has no rows"]`.
- Collect every problem before raising, in `COLUMNS` order. Row numbers are spreadsheet rows: header is row 1, so the
  first data row is row 2. List at most 5 row numbers, then `, …`. Messages, exactly:
  - ``missing column `total_cost` `` (one message per missing column; when columns are missing, skip value checks for
    those columns only)
  - ``column `surgeon` has 2 blank values (rows 4, 9)`` — blank in an `id`, `dimension`, or `date` column
  - ``column `surgery_date` has 3 values that are not dates (rows 14, 92, 310)`` — dates parse as ISO `YYYY-MM-DD`
  - ``column `total_cost` has 1 value that is not a number (row 7)``
  - ``column `total_cost` has 1 negative value (row 7)``
  - ``column `readmit_30d` has 1 value that is not yes/no (row 5)`` — booleans accept, case-insensitively,
    `1`/`0`/`true`/`false`/`yes`/`no`
  - Singular "value" for 1, plural "values" otherwise.
- Output dtypes: category → `string`, number → `float64`, boolean → pandas `boolean` (nullable), date →
  `datetime64[ns]`. Blank measures become `NA`/`NaN`. Extra columns are dropped. Adds
  `function_gain = function_post - function_pre` (NaN if either is blank).

- [ ] **Step 1: Write `tests/test_schema.py::test_filters`, `test_measures`, `test_rate_measures`.** Assert
  `[c.name for c in filters()] == ["procedure", "facility"]`;
  `[c.name for c in rate_measures()] == ["complication", "readmit_30d"]`; `measures(Kind.NUMBER)` names equal the five
  number measures in table order; every `COLUMNS` name is unique.
- [ ] **Step 2: Write `tests/test_data.py::test_load`**, parametrized over CSV text built in the test from one valid
  row dict (`VALID_ROW`). Cases (id, csv text, expected):
  - `valid`: one row → 1 row, `function_gain == post - pre`, dtypes as above
  - `excel`: BOM + `\r\n` line endings + ` surgeon ` header with spaces + `TRUE`/`FALSE` → loads, same values as
    `valid`
  - `blank measure`: blank `function_post` → loads, `function_gain` is NaN
  - `extra column`: an extra `notes` column → loads, `notes` not in output
  - `missing column`: drop `total_cost` → `DataError` with errors ``["missing column `total_cost`"]``
  - `blank dimension`: blank `surgeon` in data rows 2 and 3 of three rows →
    ``["column `surgeon` has 2 blank values (rows 3, 4)"]``
  - `bad date`, `not a number`, `negative`, `bad boolean`: one bad row each → the exact message above
  - `many bad rows`: 7 bad dates → message lists 5 rows then `, …`
  - `two problems`: missing `total_cost` and a bad date → both messages, missing column first
  - `no rows`: header only → `["the file has no rows"]`
  - `not csv`: bytes of a zip file header `b"PK\x03\x04" + bytes(100)` → `["could not read the file as CSV"]`

  Assert errors with `pytest.raises(DataError)` and `exc.value.errors == expected`.
- [ ] **Step 3: Run.** `uv run pytest tests/test_schema.py tests/test_data.py -v`. Expected: FAIL, modules not found.
- [ ] **Step 4: Implement `app/schema.py` and `app/data.py`** per the interfaces and rules above.
- [ ] **Step 5: Run.** Same command. Expected: PASS.
- [ ] **Step 6: Commit,** `make pre-pr`, push, PR.

**Acceptance criteria:**

- `test_filters`, `test_measures`, `test_rate_measures`, and every `test_load` case pass.

### T-D2: Synthetic Data Generator (HVD-11)

**Workflow:** as in "How to Use This Plan".

**Files:**

**Interfaces:**

Data rules:

- 12 surgeons, named `Dr. <Surname>` (pick 12 distinct common surnames). Case counts: two surgeons with 8 and 15
  cases, one with exactly 1 case, the rest share the remainder unevenly.
- Planted story (with seed 42): the surgeon in slot 1 has a readmission rate at least 2.5 times the overall rate;
  slot 2 has mean cost at least 25% above overall with average function gain; slot 3 has mean cost at least 15% below
  overall and function gain above overall. Record the three names as `READMIT_OUTLIER`, `HIGH_COST`, `HIGH_VALUE`
  module constants.
- Procedures: `Total Knee Replacement`, `Total Hip Replacement`, `ACL Reconstruction`, `Rotator Cuff Repair`,
  `Lumbar Spinal Fusion`, with sensible relative cost and length of stay (spinal fusion highest, rotator cuff lowest).
  Facilities: `North Campus`, `South Campus`, `Ambulatory Center`. Payer: `Medicare`, `Commercial`, `Medicaid`. Age
  group: `<50`, `50-64`, `65-74`, `75+`. Sex: `F`, `M`. ASA class: `1` to `4`; higher ASA raises cost, stay,
  complication and readmission odds.
- `surgery_date` spread over 2024-10-01 to 2026-09-30. `function_pre` and `function_post` are 0–100 integers; gain
  mostly positive. About 5% (between 3% and 7%) of `function_post` blank. No other blanks.
- Also write a `discharged_home` boolean column (higher ASA and age lowers it). The schema does not list it until
  card T-X2, so `load` drops it.
- Booleans written as `0`/`1`; costs rounded to whole dollars; `case_id` like `C00001`.
